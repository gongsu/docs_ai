# AI 코딩 시큐어코딩 가이드

AI 코딩 단계에서 보안 기준을 사전에 적용하여 개발 과정에서 발생할 수 있는 보안약점을 줄이기 위한 공통 지침입니다.
기존 시큐어코딩 진단을 대체하지 않으며, 테스트 결과 기준으로 약 50% 수준의 보안약점 감소 효과를 확인했습니다.

또한 전체 보안 기준을 매 요청마다 입력하지 않고 필요한 규칙만 선택적으로 참조하도록 구성하여, AI 모델의 토큰 사용량과 비용을 최소화하는 것을 주요 목표로 합니다.

## 파일 구성

### `COMMON_INSTRUCTIONS.md`

AI 코딩 도구가 작업을 수행할 때 따라야 하는 공통 작업 절차와 기본 원칙을 정의합니다.

* 작업 시작 전 요구사항 및 영향 범위 확인
* 코드 생성·수정 시 보안 규칙 참조
* 변경된 코드와 직접 영향 범위 중심 검토
* 불필요한 전체 규칙 반복 참조 방지

### `SECURE_CODING_RULES.md`

국내 SW 개발보안 기준을 기반으로 코드 작성 시 고려해야 할 세부 시큐어코딩 규칙을 정의합니다.

`COMMON_INSTRUCTIONS.md`에서 작업과 관련된 보안 항목만 선택적으로 참조하도록 구성하여 보안 적용 효과와 토큰 효율성을 함께 확보합니다.

## 적용 방법

프로젝트 루트에 다음 두 파일을 저장합니다.

```text
project-root/
├── COMMON_INSTRUCTIONS.md
├── SECURE_CODING_RULES.md
└── ...
```

이후 사용하는 AI 코딩 도구의 프로젝트 지침 파일에 두 파일을 우선 참고하도록 등록합니다.

| AI 코딩 도구       | 적용 파일                                   |
| -------------- | --------------------------------------- |
| OpenAI Codex   | `AGENTS.md`                             |
| Claude Code    | `CLAUDE.md`                             |
| GitHub Copilot | `.github/copilot-instructions.md`       |
| Cursor         | `.cursor/rules/common-instructions.mdc` |
| Gemini CLI     | `GEMINI.md`                             |

각 도구의 지침 파일에는 다음과 같이 두 MD 파일을 참조하도록 작성합니다.

```markdown
프로젝트 작업 시 다음 지침을 우선 적용한다.

1. 모든 작업은 `COMMON_INSTRUCTIONS.md`의 절차와 원칙을 따른다.
2. 코드 생성 또는 수정이 포함된 경우 `SECURE_CODING_RULES.md`에서 작업과 관련된 보안 규칙만 선택적으로 적용한다.
3. 작업 완료 후 변경 코드와 직접적인 영향 범위를 중심으로 보안 기준 준수 여부를 확인한다.
4. 토큰 사용량 최소화를 위해 전체 보안 규칙을 반복 출력하거나 불필요하게 재검토하지 않는다.
```

## 권장 활용 흐름

1. AI 코딩 도구가 `COMMON_INSTRUCTIONS.md`를 기본 작업 지침으로 적용
2. 코드 생성·수정 시 `SECURE_CODING_RULES.md`의 관련 항목만 선택적으로 참조
3. 개발 완료 후 변경 코드와 영향 범위 중심으로 자체 검토
4. 최종 단계에서 SAST 및 기존 시큐어코딩 진단 수행

## 참고사항

본 가이드는 AI 코딩 단계에서 보안약점을 사전에 줄이기 위한 보조 수단으로, 기존 시큐어코딩 진단이나 SAST 검증을 대체하지 않습니다.

현재 테스트에서는 약 50% 수준의 보안약점 감소 효과를 확인했으나, 적용 효과는 사용 모델, 개발 언어, 프레임워크 및 요청 방식에 따라 달라질 수 있습니다.

향후 MCP 기반 시큐어코딩 검증 기능을 추가로 검토하여 기존 진단 절차의 일부 또는 전체를 대체할 수 있는지 확인할 예정입니다.

본 가이드는 다양한 AI 모델을 대상으로 주기적인 테스트와 개선을 수행하며 관리할 예정입니다. MD 파일은 토큰 사용량과 비용을 최소화하도록 구성했으며, 프로젝트 환경과 내부 개발 기준에 따라 자유롭게 수정·보완하여 사용할 수 있습니다.
